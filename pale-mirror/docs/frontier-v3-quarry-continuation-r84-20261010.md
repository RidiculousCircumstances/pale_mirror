# Quarry work continuation / shared HOT service approach

The settlement's EXTRACTION work permission requests ongoing work. A full carried
stack is an inventory boundary, not a completed assignment. A miner deposits the
actual held output and selects another available source under the same job,
execution and exact tool. Each delivered resource part gets fresh custody/lot
identities: already transferred or sold stone cannot be reused as new output.
Hauling keeps its independent persisted batch rule.

No remaining source or a withdrawn settlement mandate ends extraction. Held
output must first be stored, then the tool returned; withdrawing an unstarted
assignment releases it without pretending to take or return a tool. Temporary
source reservations, blocked paths, storage capacity, nutrition and work windows
remain explicit waits, not fabricated completion or stock.

The old HOT movement branch stopped every service visitor anywhere on the route
when its destination service turn was unavailable. A loaded quarry courier could
therefore wait at the mine for a remote depot. Shared actor navigation now follows
an ephemeral outside approach and fences entry into the service footprint. Only
an occupant uses the separate witnessed exit protocol. Waiting-point arrival
cannot acknowledge the retained semantic goal. This applies to all registered
actor-movement service approaches, not a quarry/depot special actuator.

Canonical schema266 deliberately rejects older snapshots before replay: the old
STORE event meant tool return/job retirement, while current STORE continues the
same assignment. No historical WAL migration, silent interpretation or resource
injection is supplied. Delivery requires a fresh disposable world.

Focused source checks cover a genuine first delivery and next extraction under
the same job/tool, settled-part snapshot roundtrip, withdrawal preserving cargo,
stale/unrequested shutdown rejection, and an outside approach that permits
detours but rejects service entry/world-bound escape. These are not a measured
five-second latency improvement or a filmed second HOT delivery/restart claim.

Periodic site admission review remains200 simulation ticks; it is a recovery
review, not a delay after a confirmed item transfer. Ordinary work/shipment
receipts already wake their exact continuation at the next simulation tick.
