# Стабильные контексты расчёта и память навигации

## Подтверждённая проблема

Профили и ограничения исходного диагноза записаны в
[разборе торгового расчёта](frontier-v3-trade-feasibility.md#разбор-оставшегося-отставания-после-доставки).
Динамические keyed views создавали отдельный ThreadLocal на каждую строку/поколение,
а частая смена навигационного service-контекста попадала в очистку общей таблицы
потока. Это не основание убирать точные проверки или снижать детализацию мира.

## Границы и первый срез

`ImmutableInputView.Entry` — обычная строка с точными входами и результатом.
`ImmutableKeyedInputView` держит такие строки внутри прежней ограниченной,
изолированной по потоку таблицы производителя. Изменение поколения, ошибка или
вытеснение строки больше не создают ThreadLocal. История альтернатив остаётся
в существующем ImmutablePlanningScope; выход из решения освобождает её. Полные
равные публикации сохраняют идентичность только после успешного нового расчёта.
Стабильные производители сохраняют своё typed thread-local working state; нет
единого неограниченного реестра разнородных данных или глобальных изменяемых строк.
ExtractionWorkSafety переведён с динамических per-deposit view на тот же механизм.

`PedestrianRoutePlanning` использует один стабильный Context на вычисляющий поток.
Связь read-view, наблюдения, прочитанные доказательства, созданные запросы,
inspection и service — обычные поля с вложенным сохранением/восстановлением.
Все ссылки задачи обнуляются/восстанавливаются при выходе; пустой Context не
удерживает геометрию или мир. В observe восстановление выполняется до fallible
cleanup callback, поэтому исключение discard не оставляет контекст следующей
задаче. Только принятый owner completion по-прежнему приобретает зависимости;
чтение на worker не запускает живой поиск, не коммитит событие и не даёт arrival.

Изменений схемы, параметров экономики, весов/сроков очереди или размеров пулов нет.
Первый срез измеряется отдельно от последующей оптимизации геометрии.

## Геометрия: точные колонки без временных ключей

`ProfiledPedestrianGeometry` хранит ColumnFacts в `BoundedLongMemo` с прежним
пределом8192. Пара полных signed int X/Z упакована без потери информации в long;
новая версия геометрии/профиль создают прежний отдельный decorator. Не добавлено
межверсионного права повторно использовать факты или новой модели поверхности.

Общий BoundedLongMemo хранит ключи, bucket index и LRU-связи в массивах; get/put
не создают boxed keys или hash nodes. Полное сравнение long определяет попадание;
смешанный hash выбирает только bucket. Вытеснение закрывает probe-chain hole, не
накапливает tombstones. Таблица растёт с64 строк до объявленного предела; маленький
поиск не резервирует максимальную ёмкость. Вычисление отсутствующих фактов остаётся
вне монитора, несколько читателей могут безопасно получить один immutable результат.

Проверка сравнивает рост, замену, попадания и длительное вытеснение с независимым
LinkedHashMap LRU, включая полный диапазон ключей и коллизии. Все171 релевантных
Java проверок и55 нативных экономических GameTest прошли; guardrails/JAR/package
прошли. Это затронутое покрытие; два прежних несвязанных отказа NeoForge unit suite
из исходного отчёта не объявляются исправленными. Нативные GameTest выполнены после
окончания измеряемого ordinary окна первого среза, без перекрытия нагрузок.


## Уточнение по региональным чтениям

Промежуточный525cf показал9,536 тика/с против8,409 исходного и8,664 context-only
на том же сохранении. Профиль подтвердил устранение ThreadLocal hotspot, но не
большое сокращение суммарных навигационных выделений. Дополнительный статический
разбор этого же профиля выявил замену единственной last-page записи при соседних
чтениях и повторную сборку полного neighbour tuple в lazy wide-profile revision.

ImmutableRegionMap теперь лениво держит окно8 точных неизменяемых страниц с
атомарной публикацией. Проверяется полная пара координат, включая отсутствующую
страницу; коллизия слота лишь вызывает повторное чтение. Нет per-map ThreadLocal,
неограниченной истории или смены authoritative данных.
PedestrianGeometryRevision читает X/Z непосредственно и мемоизирует до256 полных
расширенных региональных фактов внутри своей неизменяемой terrain capture через
тот же BoundedLongMemo. Отсутствие отмечено внутренним непубликуемым sentinel;
оно не превращается в проходимую клетку. Изменение источника создаёт новую revision;
полная materialization освобождает временную таблицу. Совпадение hash не заменяет
равенство фактов. Кэшированная/вытесненная/материализованная картина и изменение
соседнего отсутствующего региона проверены отдельным семантическим случаем.
