# Crossbow contact defence

Crossbow combat permissions now explicitly admit the existing KICK at its
shared skill20 threshold. This is a close self-defence action; it grants no
sword attack, formation slot, melee pursuit or additional movement authority.
A guard below20 retains ordinary ranged retreat without this learned move.

The bounded native combat pass checks actual nearby target hitbox/LOS, current
body/equipment authority and clear contact. It submits the same observed stance
and MeleeStrike preparation as ordinary contact combat. Shared canonical
admission owns effort, cooldown, exact actor/weapon/target/attempt and pending
obligations. Shared native presentation, durable MELEE_ATTACK operation and
confirmation own the kick effect. Native collision/reach/arc/finite timing and
hurt acceptance still decide whether it hits. A kick hit applies the existing
strength-dependent knockback; it spends neither personal arrows nor crossbow
wear. An enemy that backs out of contact receives no remote kick.

A pending arrow preparation and its recovery prevent kick admission; a pending
kick and common recovery prevent starting a shot. The ranged owner can continue
its existing retreat after contact. No direct actuator, extra damage loop, COLD
fight, inventory synthesis, codec field or schema change is added. Existing
wire346/r34world can continue through a normal verified restart.

Focused domain tests exercise successful guard contact preparation/completion,
zero ammunition/wear debit, cooldown, snapshot/replay rejection, pending-arrow
exclusion and absence of sword permissions. Existing native durable-contact
fixture now also uses an actual held crossbow/personal arrows: both kick hit
with real knockback and retreating-target miss use the same journal, cue and
no-replay check. Test fixtures are unit preconditions, not a player fight or M3
claim. Actual checks and deployment identity are in CONTINUITY.md.
